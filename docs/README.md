# 文档目录

`docs/` 分两层：**通用**（与项目无关，可整目录拷进任何新项目）与 **项目**（dshdt 专属）。
总入口是 [`项目/00-文档导航.md`](项目/00-文档导航.md) —— 新会话请从那里开始。

## 通用/ — 可复用到任何项目

| 文件 | 内容 |
|---|---|
| [`01-代码规范.md`](通用/01-代码规范.md) | 命名、目录、风格、错误处理、状态可逆、配置与密钥、日志、依赖、安全（§11 是移植清单） |
| [`02-提交与门禁.md`](通用/02-提交与门禁.md) | 提交信息规范、门禁分层、检查点协议、版本与发布纪律、公开仓库前体检清单 |
| [`03-AI协作与文档义务.md`](通用/03-AI协作与文档义务.md) | 单一事实源、开工清单模板、交接便条模板、文档同步矩阵、协作铁律、§7 文风 |
| [`04-排障方法与通用坑.md`](通用/04-排障方法与通用坑.md) | 六步排障法、坑清单模板、Windows/Node/文件系统/Electron 通用坑、验证技法、判据表 |

拷进新项目后，按 `01-代码规范.md` §11 的清单改 8 处即可用。

## 项目/ — dshdt 专属

| 文件 | 内容 |
|---|---|
| [`00-文档导航.md`](项目/00-文档导航.md) | **入口**：目录结构、我该读哪份、旧→新文书对照表、维护义务 |
| [`01-新会话开工清单.md`](项目/01-新会话开工清单.md) | 状态锚点与交接便条（活页，每次收工重写） |
| [`02-架构与铁律.md`](项目/02-架构与铁律.md) | 项目铁律、工程地图、代码风格落点、DSH 侧规则、命名 |
| [`03-坑清单.md`](项目/03-坑清单.md) | 编号坑 1~63（现象 / 根因 / 修法 / 验证 / 通用教训）；全仓库的 `见坑 N` 都指向这里 |
| [`04-范例与检查点.md`](项目/04-范例与检查点.md) | 端到端代码范例、检查点命令清单、提交规范 |
| [`计划/`](项目/计划/) | 四份计划与进度文书；`Electron施工计划与进度.md` 是**唯一进度事实源** |

## 维护义务

1. **新坑回填** `项目/03-坑清单.md`（编号顺延，不重排、不删旧条目）；换个项目也会遇到的，同时补进 `通用/04`。
2. **同一事实只写一处**，其他地方引用它 —— 进度只写 `项目/计划/Electron施工计划与进度.md` 与根 `CHANGELOG.md`。
3. 每次改动按 [`通用/03-AI协作与文档义务.md`](通用/03-AI协作与文档义务.md) §4 的**文档同步矩阵**更新，同一个 commit 内完成。
4. 对外文本（README / 仓库简介 / Release / 提交说明）按 `通用/03` §7 的**「克制专业」**文风写。
