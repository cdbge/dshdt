## 1. 项目铁律（不可违背）

1. **DSH 零改动**：不修改 DSH（harness）源码。壳侧一切能力走 `--port` / `--patch` / 回环 admin API / 环境变量 / 浏览器 CSS 注入。自研插件只落在 `profiles/web/node_modules/<包名>`（out-of-tree 插件位）并经 patch `insert` 挂载。
2. **每次改动必须更新计划书**：《Electron施工计划与进度.md》的"进度快照"表与对应阶段小节；《DeepSeek-Harness桌面应用封装计划书.md》《Electron构建安装包计划书.md》按需补能力表/坑清单。**这是硬性要求，不是可选动作。**
3. **打包与更新必须先经用户同意（2026-09-08 起用户确认的硬规矩）**：
   - 跑 `electron-builder` 产出安装包（exe）→ **必须先征得用户同意与确认**，不得自行打包；
   - 对用户已装应用做 asar 热更新/替换 → 同样先征得同意；
   - 同意后打包仍须跑完第 4 条门禁；打包产物冒烟（`win-unpacked --smoke`）也要跑。
4. **门禁顺序**（改完任何东西后）：
   ```powershell
   node --check <改动文件>          # 语法
   node scripts/repair-self-test.mjs  # 会话日志自愈单测（动了 repair.mjs 才跑）
   node scripts/admin-bg-test.mjs     # admin 背景图单测（动了 admin.mjs 才跑）
   node scripts/smoke.mjs             # 全量 e2e 冒烟（任何壳代码改动必跑）
   # 发版才跑（且需用户同意）：build-host --prune-only（vendor 变了）→ electron-builder（打包）
   ```
   检查点失败 = 未完成，修复后重跑，**不"口头通过"**。
5. **不 commit 不进下一阶段**；commit message 带阶段/版本前缀（如 `fix(0.4.2): ...`）。
6. 行为契约先行：v1（Node + Chrome app-mode 壳，**目录已不在本仓库**，只存于 git 历史）与 Electron 分支的 admin API 面保持一致，smoke 断言是契约的执行者。
7. **版本号推进须经用户允许（2026-09-11 用户指示，硬规矩）**：未经用户明确同意，**不得**改动 `VERSION` / `package.json` / `CHANGELOG` 里的版本号，也不得据此命名迁移/备份目录与产物；功能照常开发、提交、更新文书，但**版本号保持用户指定的值**；要发新版必须先由用户点名。

## 2. 工程地图（desktop-electron/）

| 文件 | 职责 |
|---|---|
| `src/main.mjs` | 主进程：多窗口、host 复用编排（`.dsh-host.lock` + netstat 探测）、窗口/托盘/协议/退出（优雅停宿主）、背景图 CSS 注入（穿透 rc.6 不透明层）、admin 装配 |
| `src/node-guard.mjs` | 运行环境保护（main.mjs **第一个** import）：防 `ELECTRON_RUN_AS_NODE` 泄漏导致主进程退化成纯 Node |
| `src/early-errors.mjs` | 打包态未捕获异常落盘（main.mjs 第二个 import） |
| `src/host.mjs` | 模式 B 宿主托管：findDshBin / freePort / waitReady / killTree / startHost（RUN_AS_NODE + `--expose-internals` + `SSH_CONNECTION=dsh-desktop-browse` 钉住应用内目录浏览） |
| `src/dsh-update.mjs` | DSH 更新按钮 S1：版本**发现**（parseVersion / compareVersions / pickHighestVersion / readCurrentVersions / fetchPackument / checkForUpdate）。纯 Node、不写文件、不起进程 |
| `src/vendor-build.mjs` | DSH 更新按钮 S2：vendor 树**构建原语**（npm 探测 / install / 剪枝 / `syncVendorPlugins` / ABI 门禁 / lock / `buildStaging`）。**必须在 src/ 而非 scripts/——后者不进包**，见坑 27 |
| `src/dsh-apply.mjs` | DSH 更新按钮 S3：待应用标记（`pending-vendor.json`）、暂存树校验、`swapVendorTree` 换树、旧树清理。全同步、纯 Node。**换树唯一不可逆，每条失败分支都有单测** |
| `src/junction-safe.mjs` | junction 安全删除（`safeRemoveTree`）与遗留门禁目录清理（`cleanStaleBootGateHomes`）。**凡自己删可能含 junction 的目录都必须走它**，见坑 38 |
| `src/admin.mjs` | 回环 admin HTTP：`/api/*` + `/bg-image`（背景图供给）+ CORS（仅回环来源） |
| `src/repair.mjs` | 会话日志自愈：半个 zstd 尾帧截断 / 首帧异常逐行重编码 / 无法修复隔离改名 |
| `src/desktop.patch.yml` | 形态层 patch（web-runtime config 整体替换 + dsh-desktop-ui insert） |
| `packages/dsh-desktop-ui/` | 客户端插件：设置面板"桌面"section（`settings.section` 槽位）；按钮 ghost + hover/active 交互样式（`.dsh-desktop-btn` 注入样式表）；双副本同步路径见坑 13 |
| `scripts/` | 门禁与工具：smoke（**72** 断言）/ repair-self-test（8）/ admin-bg-test（7）/ update-self-test（36）/ vendor-build-self-test（66）/ dsh-apply-self-test（44）/ junction-safe-self-test（18）/ **patch-mount-self-test（16，profile 补丁层挂载与自愈）**/ vendor-equivalence（暂存树验证，重）/ gen-icon / boot-smoke（一次性像素探针、CDP 悬停探针与选择器崩溃复现脚本已于 2026-09-13 清理，技法见 `docs/通用/04-排障方法与通用坑.md` §8）；`build-host` 与 `abi-scan` 已退化为 CLI 薄封装（实现在 `src/vendor-build.mjs`） |
| `packages/dsh-auto-approval/` | 服务端插件：**AI 自行裁决权限申请**——审批瀑布上以 `{ global: true, prepend: true }` 抢在用户弹窗之前；关键词表**只作证据**，裁决权交给一次独立模型调用（走本体 `agent-default-model` + 统一 Key，插件零配置）；`/approval` 开关命令；决策日志 `$DSH_HOME\logs\auto-approval.log`。**改它必须重启宿主**（源码不热加载）。见坑 48/49/50/52 |
| `vendor/profile/` | 自包含 DSH 运行时（**0.1.5-rc.2** 锁定，与已装应用同版），build-host.mjs 生成，勿手改 |
| `build/icon.ico` | 唯一图标源（BrowserWindow/Tray/electron-builder 共用），由 `gen-icon.mjs` 从 workspace 根 `dsh.jpeg` 生成 |
| `$DSH_HOME/profiles/web/…` | HOME profile：`node_modules/dsh-desktop-ui`（客户端插件）+ `node_modules/dsh-auto-approval`（审批插件）——**两份副本**，壳启动幂等同步；+ `dsh-host-lock-registry`（纯登记 `.dsh-host.lock`，不拦截不退出）|

命名：文件 kebab-case；环境变量 `DSH_` 前缀（`DSH_HOME`/`DSH_WS`/`DSH_BIN`/`DSH_APP_DATA`/`DSH_SMOKE`）；admin API `/api/<小写名词>`；日志 `app.log`/`host.log` 按天轮转留 7 天；版本独立 semver + 根 `VERSION` 文件 + CHANGELOG 条目。

## 3. 代码风格

- **注释用中文**，模块头注释写"为什么"而非"是什么"；关键决策注释引用实证依据（如 #1452、评审稿编号）。
- **同步优先**：`fs` 用同步 API + try/catch（主进程小文件场景）；async 仅用于 fetch/等待/对话框。
- 函数小、单一职责；错误逐层 `log()` 不吞；`log()` 自己容忍目录不可写（console 兜底）。
- 所有副作用可逆：锁要释放、CSS 要 `removeInsertedCSS`、事件监听有 disposer。
- 状态文件/锁文件读写在模块内收敛为 `readState/writeState/readHostLock/writeHostLock/releaseHostLockIfOurs`，不散落。

## 4. DSH 侧规则（零改动承诺的边界）

1. **不改 DSH 源码**；壳侧一切走 `--port` / `--patch` / 回环 admin API / 环境变量。
2. **patch 按行 id 定位，config 是整体替换语义**：改某行 config 必须带全该行全部键（如 web-runtime 的 trustedHosts/surfaceContext）。
3. **bundles 锁精确版本**（仓库当前为 0.1.5-rc.2）；升级走 build-host 全量重建 + 双冒烟门禁。
4. profile 的模块解析是「双锚」机制，与包管理器无关（pnpm 只在 `dsh plugin` CLI 场景需要）。
5. 宿主入口复用 dsh 包自带 `lib/bin.js`，不自行重写 runProfile 编排。
6. **loader 对插件条目做 ESM 解析的基准是 profile 目录本身**（`$DSH_HOME/profiles/web/`）：自研插件包必须落到 out-of-tree 插件位 `profiles/web/node_modules/<包名>`（`dsh plugin` 机制的落点）——vendor/profile 里的副本不会被父级解析覆盖到（ERR_MODULE_NOT_FOUND 实证）。壳启动时幂等同步（`ensureProfilePlugin`）。

## 5. 命名（本项目落点）

通用规则见 `docs/通用/01-代码规范.md` §1；下表是本项目的具体实例。

| 域 | 规则 | 实例 |
|---|---|---|
| 文件 | kebab-case，小写连字符 | `main.mjs` `host.mjs` `build-host.mjs` `boot-smoke.mjs` `abi-scan.mjs` `desktop.patch.yml` |
| 目录 | 职责单一：`src/`（壳代码）、`scripts/`（构建/门禁）、`vendor/profile`（自包含运行时）、`build/`（打包资源）、`dist/`（产物） | — |
| 环境变量 | 统一 `DSH_` 前缀，作用即名 | `DSH_HOME` `DSH_WS` `DSH_BIN` `DSH_APP_DATA` `DSH_SMOKE` |
| admin API | `/api/<小写名词>`，与 v1 契约一致 | `/api/status` `/api/workspace` `/api/quit` |
| 测试目录 | `.dsh-m*` / `.dsh-pkg*`（gitignore 覆盖） | `.dsh-m0` `.dsh-pkg-home` |
| 日志 | `app.log` / `host.log`，轮转 `名.log.YYYYMMDD`，留 7 天 | `host.log.20260818` |
| commit | `<类型>(<范围>): <中文动作>（关键数字）` | `feat(0.4.6): 宿主崩溃可诊断`、`chore(repo): 开源前清理工作区` |
| 版本 | 壳独立 semver + 根 `VERSION` 文件 + CHANGELOG 条目；DSH 依赖锁版本进 `vendor.lock.json` | `0.4.6` |
| 门禁脚本 | 幂等、可重复、有 exit code；输出 `PASS/FAIL` 行 | `smoke.mjs` `abi-scan.mjs` |
