# 通用：排障方法与跨项目坑清单

> **适用范围**：任何在 **Windows + Node/PowerShell + 桌面壳/打包** 这条链路上跑的项目
> （绝大多数条目与语言无关，属于"操作系统与工具链的行为"）。
> **核心命题**：**排障时间 80% 花在"收集信息"和"分错类"上**，只有 20% 花在修复。本文就是为这 80% 写的。
> 配套：`01-代码规范.md`、`02-提交与门禁.md`、`03-AI协作与文档义务.md`。
> 项目专属坑见各项目的坑清单（本文只收"换个项目还会遇到"的）。

---

## 1. 排障方法论（六步，顺序不能反）

```
① 分类    →  是「代码缺陷」「环境不允许」还是「使用错误」？（见 §9 判据表）
② 分离变量 →  一次只动一个变量；换环境/换参数/换样本，逐个排除
③ 最小复现 →  把现象缩到一条命令 / 一个文件 / 一个断言
④ 取证    →  日志尾部、退出码、状态文件、环境变量、版本、文件数（能自动化的写成 --diag）
⑤ 修复    →  改最小的那一处；不可逆操作先写单测
⑥ 验证+回填 →  用"真实坏样本"端到端验证，然后把这条坑写进坑清单
```

**四条纪律**：
1. **不要在没分类前就改代码**。在受限环境里失败，十有八九不是代码的问题（实测：把沙箱限制误判成"程序自杀"，白耗十几轮并据此做出错误推理）。
2. **不要相信单一信号**。退出码可能是伪影、日志可能被吞、UI 可能"看起来好了"——**至少两个独立证据**才算确认。
3. **不要在没有复现的情况下宣布修复**。能复现旧版本的问题，才能证明新版本修好了。
4. **不要重复踩已记录的坑**。动手前先读坑清单；踩了新的就当场回填（含你走的弯路）。

## 2. 坑清单条目模板

每条坑都按这六项写，缺一项这条坑的价值就折半：

```markdown
N. **<一句话结论，带"现象"关键词>**（<版本/日期> 实证）：
   现象：<用户看到什么 / 日志里出现什么>
   根因：<机制层面的解释，指到具体代码/变量/系统行为>
   修法：<具体动作，含"不要怎么做">
   验证：<用什么命令/断言证明修好了>
   通用教训：<一句话，能带到别的项目去>
```

**"通用教训"是最值钱的一行**。例：*"往别人的模板文件里追加内容前，先看那个模板的末行是什么形态"*——这句话在 YAML、JSON、INI、任何配置系统里都成立。

## 3. Windows / PowerShell

1. **`&` 不等待 GUI 程序返回**：后台任务会"提前完成"，进程还在跑。要等待用 `Start-Process -PassThru -Wait`，或 `cmd /c`（它对 GUI 进程也等）。验证存活用状态文件/端口轮询，不要靠"命令返回了"。
2. **变量名不区分大小写**：`$asar` 与 `$ASAR` 是同一个变量，互相覆盖。报错形态会完全骗人（实测：表现为"工具读不了这个归档"，误判成工具损坏）。**同名变量必须在忽略大小写之外仍可区分**。
3. **`$home`/`$pid`/`$pwd` 等是只读自动变量**：脚本里别拿它们当自己的变量名。
4. **Windows PowerShell 5.1 ≠ PowerShell 7**：`-AsByteStream` 等 7.x 参数在 5.1 不可用；读字节用 .NET API。写脚本前先确认执行环境版本。
5. **读 UTF-8 无 BOM 文件可能按 GBK 解码**：显示乱码 / JSON 解析失败。用能显式指定编码的工具读（或干脆用 `node` 读）。写文件时也显式指定"无 BOM UTF-8"。
6. **环境变量只对新进程生效**：`setx` 改完，已存在的进程（包括当前会话）读不到；脚本内部要显式带上。
7. **无 UI 的会话里，需要交互确认的操作会无声挂起**：SmartScreen、证书信任、UAC、安装器——进程活着、无输出、无窗口。这类步骤必须交给有桌面的会话，或者事先配置好。
8. **`netstat -ano -p tcp` 解析 PID→端口**，比 WMI/CIM 可靠（后者可能被策略禁用且慢）。
9. **权限分层要提前分类**：GUI 进程、命名管道、原生模块加载在受限环境里会被拦（表现为"超时""拒绝访问 (0x5)"）。把"哪些命令需要更宽权限"写进文书。
11. **TLS 失败 ≠ 断网**：`SEC_E_NO_CREDENTIALS`（schannel）这类报错是**本机 TLS 后端**的问题 —— DNS 与 TCP 可能完全正常。先按 **DNS → TCP → TLS → 认证** 四层定位；同一台机器上不同程序的 TLS 栈可以一个坏一个好，**换后端/换运行时**通常立刻见效（如 `git -c http.sslBackend=openssl`、改用自带 OpenSSL 的 node）。
12. **受限环境会拦命名管道**：脚本宿主（`sh.exe`、部分 `cmd` 组合）可能**连启动都失败**（`couldn't create signal pipe, Win32 error 5`），于是依赖它们的机制整体失效（git 的 `!`-前缀 credential helper、某些 `spawn` 组合）。**优先改用原生可执行文件**，不要跟限制硬碰。
13. **给命令行传含引号的长文本，先存变量**：shell 会在嵌套双引号处静默截断参数，症状是「命令执行了但没生效」（提交没发生、参数被当成路径）。多行文本用 here-string；**做完用一条独立断言确认副作用真的发生**（`git log -1`、`git status`），而不是只看退出码。
10. **卸载重装不清理用户目录**：坏状态留在 `%USERPROFILE%\.<app>` / `%LOCALAPPDATA%\<App>`，重装一千次也没用。排障第一步是**改名（不是删）**这些目录来二分。

## 4. Node / npm / 子进程

1. **子进程默认 `pipe` stdio 在受限环境会 `EPERM`**：退化方案是文件描述符重定向或 `stdio:'ignore'`/`'inherit'`。但**不要把退化当成默认**——真实用户机器上**管道才是唯一能拿到"子进程最后遗言"的通道**（fd 直通时父进程不读，崩溃时 stderr 随进程消失，日志里只剩一行"--- run ---"）。
   **正确姿态是两级**：先探测管道可用性 → 可用则 `['ignore','pipe','pipe']` + 实时落盘 + 环形缓冲（保留最后几行，崩溃时写进通知与日志）→ 被拒则退化 fd 保功能，**并在诊断里留痕**。
2. **探测 `spawn` 可用性不能用 `try/catch`**：Windows 上 spawn 失败是**异步 `'error'` 事件**，同步 catch 接不到 → 得到"假成功"（child 已死却照常返回），表现为"一个字节都不输出、30 秒后判超时"，比原问题更隐蔽。要用 `spawnSync` 拿同步 `error`。
3. **npm 垫片不可 spawn**：Windows 上 `spawn('npm')` 可能 `ENOENT`（PATH 里只有 `npm.ps1`）。从 `dirname(process.execPath)/node_modules/npm/bin/npm-cli.js` 推导，用 node 直调；同理 `npx` 换成 `node node_modules/<tool>/out/cli/cli.js`。
4. **registry 直连可能无限挂起且不报错**：无代理环境访问公共 registry 会静默卡住。构建脚本**强制显式镜像**（`npm_config_registry`），并**显式指定可写的 cache 目录**（外部传入坏值时无条件覆盖）。
5. **ESM 导入 CJS 的命名导出可能检测不到**：运行时报 `SyntaxError: Named export not found`。一律 `import pkg from 'cjs-pkg'; const { x } = pkg`。
6. **环境变量会顺着进程树泄漏**：典型是 `ELECTRON_RUN_AS_NODE=1`——它让 Electron 退化成纯 Node，GUI 程序报"无此导出"且**无窗口无日志**。程序入口要有守卫（检测到就报错退出并说清原因），人和脚本在启动 GUI 前也要清理它。
7. **同步优先**：小文件、小状态、启动路径用同步 API + `try/catch`；异步只留给真正的等待。为了"优雅"而异步化，会把错误堆栈拆散、把简单问题复杂化。
8. **子进程参数用数组**：路径含空格（`Program Files`）时字符串拼接必炸。

## 5. 工具输出与流水线契约

1. **断言名不得以 `PASS`/`FAIL` 开头**：`  PASS  FAIL 带上了原因` 会让任何 `grep FAIL` 的流水线把全绿读成失败。门禁脚本的**输出格式就是它的对外契约**。
2. **成功标记比退出码更可信**（在沙箱/包装器下尤其）：GUI 进程的退出码可能是环境伪影（实测：成功却返回 `-2147483645`）。**以日志中的成功标记为准**，并把这条写进文书。
3. **`null` 兼表"未初始化"与"无约束"，会让守卫静默失效**：守卫写成 `if (target !== null && version !== target) reject`，而 `target === null` 的真实含义是"从未检查过"——于是任意值都能绕过。**"未初始化"必须单独拒绝，并为它单独写一条断言。**
4. **断言要打在正确的对象上**：状态文件里的字段集与 HTTP 响应里的字段集常常不同（一个给进程自己用、一个给 UI 用）。打错就是"字段不存在"的假失败。
5. **`res.ok` 不等于"服务就绪"**：真实服务可能先返回 `303` 换 cookie，而 `fetch` 没有 cookie jar——默认跟随重定向会丢 `Set-Cookie`，下一跳 401，于是"永远探不到就绪"。就绪探测要么做完整握手，要么只要求"服务器回了任何 HTTP 响应"，把带 token 的 URL 交给真正的客户端。

## 6. 文件系统、编码、链接

1. **递归删除可能跟随链接**：Node 的 `fs.rmSync(recursive)` 不跟随 junction/symlink，但 **Windows 的 `rmdir /s /q`、`del /s /q` 会跟随**——实测把目标目录**掏空成空目录**（"目录还在、文件全没"就是这个特征）。凡删除可能含链接的目录，一律走自己的安全删除器（显式判链接、跳过、只删链接本身）。
2. **判"多久没动过"用 birthtime，不用 mtime**：内容一变 mtime 就刷新，用 mtime 判断年龄会误伤新文件。
3. **路径校验顺序**：存在性 → 类型（文件/目录）→ 扩展名白名单 → 规范化 → 再使用。
4. **写别人的模板文件前先看末行**：`[]`/`{}` 这种"空文档字面量"后面追加任何内容都会变成**第二个文档**（YAML/JSON 直接损坏，且很多解析器只读第一个）。幂等写入必须用**解析结果**判断，不能靠"名字出现过没有"。
5. **诊断/导出目录最容易漏出明文凭据**：快照类目录（配置导出、更新前备份）里常有 `.credentials.yaml`、`.env`。清理与 gitignore 都要专门覆盖它们。

## 7. 桌面壳 / Electron（做桌面应用才有）

1. **打包态未捕获异常 = 无窗口静默挂起**：原生对话框卡死、进程不死、无日志。**第一个 import 必须是"未捕获异常落盘"模块**。
2. **渲染层不能加载 `file://` 本地资源**（"Not allowed to load local resource"）：给页面用的本地文件必须走**回环 HTTP 供给**（MIME 白名单 + `Cache-Control: no-store` + `?t=mtime` 破缓存）。
3. **打包器只收配置里声明的目录**：`scripts/` 通常不进包。**运行时要调用的能力放在会被打包的目录**（踩过：门禁代码在打包后根本不存在）。
4. **拷贝规则的坑**：`extraResources.from` 不能以 `node_modules` 为根（拷贝过滤器会整棵跳过，只剩 `package.json`）——把 `from` 上提到父目录。
5. **平台二进制必须 unpack**：`*.node`、`@img/**` 等放进 asar 后系统加载器读不到。
6. **签名时间戳服务器可能不可达**：带证书环境变量的构建会超时失败；无网时**出未签名包**（首次运行 SmartScreen 提示属预期，要在 README 里写明）。
7. **热更新要换"所有副本"**：同一个文件常常有"打包内 / 安装目录 / 用户 profile"多份（实测三份），只换一份会出现"改了没生效"。
8. **asar 热更新必须"解包已装 asar 再覆写重打"**：从零打包会丢掉生产依赖。

## 8. 验证技法（能证明"真的成了"的手段）

| 现象类别 | 廉价验证 | 强验证 |
|---|---|---|
| 逻辑/状态机 | 纯函数单测（脱网、秒级） | 状态机全分支 + 失败分支各一条断言 |
| 服务就绪 | 端口探测 | 完整握手（含 303→cookie→200）+ 真起一次 |
| UI 样式 | 计算样式断言 | **像素级**：`elementsFromPoint` + 截图前后角落像素必须变化 |
| 交互（hover/点击） | DOM 断言 | **CDP 实测**：`Input.dispatchMouseEvent` 移动鼠标，对比 rest→hover 的计算样式（注意：隐藏窗口里 mouse-away 未必刷新 `:hover`，以 rest→hover 的变化为准） |
| 修复线上问题 | 单元测试 | **用真实坏样本喂真实产物**（端到端复现，再看日志里的修复记录） |
| 打包质量 | 打包成功 | 打包产物在**隔离 home** 下真跑一次冒烟 |

**"计算样式正确 ≠ 视觉可见"**：注入成功、资源加载成功、样式表全对，画面仍可能被一个写死不透明的层盖住。**UI 类改动必须做像素级验证**，否则你只是在验证"我以为"。

## 9. 判据表：快速分类

| 症状 | 先查（按顺序） | 大概率属于 |
|---|---|---|
| 启动即退出、`code=1` | 日志尾部 → 配置文件是否被写坏 → 用户目录残留 | 代码/配置缺陷 |
| 无窗口、无日志、静默挂起 | 是否缺"未捕获异常落盘"；是否弹了原生对话框 | 代码缺陷 |
| 提示"拒绝访问 (0x5)"/命名管道 | 当前权限模式；是否 GUI 进程/原生模块 | **环境不允许** |
| 一个字节都不输出、之后超时 | 子进程 stdio 模式（pipe 被拒？）；探测方式是否用了同步 catch | 代码缺陷（探测写错） |
| "改了没生效" | 有几份副本？加载的是哪一份？是否要重启？ | 使用/流程错误 |
| 重装也没用 | 用户目录里的坏状态（改名二分） | 残留状态 |
| 网络相关命令卡死无报错 | registry/镜像配置；代理；DNS | **环境不允许** |
| 只在别人机器上复现 | 环境差异：杀软、组策略、路径含中文、全局环境变量、精简版系统 | 环境不允许 |
