# 通用代码规范

> **适用范围**：任何新项目。本文与具体语言、框架、业务无关；涉及语言差异的地方用「示例」标注。
> **用法**：拷进新项目的 `docs/通用/`，然后按 §11 的移植清单改 8 处即可用。
> **维护义务**：踩到新坑、定下新约定，**先改本文再改代码**——规范不是事后总结，是动手前的输入。
> 配套三份：`02-提交与门禁.md`（怎么交付）、`03-AI协作与文档义务.md`（怎么接力）、`04-排障方法与通用坑.md`（怎么查错）。

---

## 1. 命名

命名是唯一"改起来最贵"的东西，早期定死，后期只增不改。

| 对象 | 规则 | 示例 |
|---|---|---|
| 文件 | `kebab-case`，小写连字符；不用空格、不用下划线、不用中文 | `main.mjs` `build-host.mjs` `dsh-update.mjs` |
| 目录 | 按**职责**分，不按文件类型分 | `src/`（源码）`scripts/`（构建与门禁）`build/`（打包资源）`dist/`（产物）`docs/`（文书） |
| 变量/函数 | `camelCase`；函数名以**动词**开头 | `readSettings` `applyBackgroundCss` `safeRemoveTree` |
| 常量 | `UPPER_SNAKE_CASE`，模块顶部集中声明 | `VENDOR_EXPECT_FILES` `BG_ALLOWED_EXT` |
| 布尔 | `is/has/can/should` 前缀，禁止 `flag`/`tmp`/`data2` | `isPackaged` `hasUpdate` `canSwap` |
| 类/类型 | `PascalCase` | `VendorStagingTree` |
| 环境变量 | 统一项目前缀 + `UPPER_SNAKE`；**作用即名** | `DSH_HOME` `DSH_WS` `DSH_SMOKE` |
| HTTP 接口 | `/api/<小写名词>`，动词交给方法 | `GET /api/status`、`POST /api/workspace` |
| 日志文件 | `<来源>.log`，按天轮转 `<来源>.log.YYYYMMDD`，**保留 7 天** | `app.log` `host.log.20260907` |
| 测试/临时目录 | 固定前缀 + 任意后缀，且**必须被 gitignore 覆盖** | `.dsh-m0/` `.dsh-pkg-home/` |
| 分支 | `main`（可发布）+ `feat/<短名>` `fix/<短名>` | `fix/profile-patch-mount` |
| 产物 | `<产品名>-<类型>-<版本>.<ext>`；变更备份加日期后缀 | `DSHDesktop-Setup-0.4.6.exe`、`app.asar.bak-20260912-1728` |
| 版本 | semver；**单一事实源**（一个 `VERSION` 文件），代码与产物都从它读 | `0.4.6` |

铁律：
1. **同一个名字在不同地方含义必须一致**，同一个含义不要有两个名字。
2. **脚本变量名要在"忽略大小写"之外仍然可区分**——PowerShell 等语言里 `$asar` 与 `$ASAR` 是同一个变量，覆盖后报错形态会骗你（踩过）。用 `$asarCli` / `$asarFile`。
3. 备份/归档一律带**时间戳后缀**，不要叫 `old/`、`new/`、`final/`、`最终版2/`。

## 2. 目录与文件组织

- **源码与产物分离**：产物目录（`dist/`、生成物）永远不进版本库，见 `02-提交与门禁.md` §5。
- **会进产物的代码，不能放在只给开发用的目录里**：打包器通常只收 `src/**`。凡是"运行时/装机后要调用"的能力，必须落在会被打包的目录；`scripts/` 只放开发期工具。这条踩过很贵的坑（门禁代码打包后根本不存在）。
- **一个目录一个职责**：判断标准是"能不能用一句话说清它装什么"，说不清就拆。
- 入口文件要有**明确的失败兜底**：进程级未捕获异常必须最先注册落盘逻辑，否则打包态崩了就是"无窗口、无日志、静默挂起"。

## 3. 代码风格

- **函数小、单一职责**：一个函数只做一件事，行数超过一屏就拆。
- **注释写「为什么」，不写「是什么」**：代码本身说明了 what，注释要留下 why 与依据。关键决策必须引用**实证来源**（实测结论、问题编号、评审稿），让后来者能复核。
  ```js
  // 不能用 try { spawn(pipe) } catch {} 探测：Windows 上 spawn 失败是异步 'error' 事件，
  // 同步 catch 接不到 —— 会得到"假成功"，child 已死却照常返回（实测，比原问题更隐蔽）
  ```
- **并发模型选最可预测的那个**：能用同步 API 就用同步（小文件、小状态、启动路径）；异步只留给**真正等待**的地方（网络、对话框、长任务）。不要为了"现代化"把同步逻辑异步化。
- **不吞异常**：`catch` 里必须有动作（记录 + 降级 或 记录 + 抛出），禁止空 `catch {}`。
- **降级要留痕**：功能退化（如管道不可用退回文件描述符）必须在日志/诊断里说清楚"我降级了、为什么"。
- **默认 fail-closed**：安全/权限/校验相关的判断，不确定时按"拒绝"处理，而不是放行。
- **格式交给工具**：缩进、引号、换行由 formatter 决定，人不在评审里吵风格。

## 4. 错误处理与失败姿态

1. **错误信息 = 现象 + 依据 + 下一步**。反面：「出错了」。正面：「宿主未就绪：管道被拒（EPERM），已降级为 fd 模式，请查看 host.log 最后 20 行」。
2. **区分「用户错误」「环境不允许」「代码缺陷」三类**，三类的处置完全不同（见 `04-排障方法与通用坑.md` §1）。日志里要能一眼分清。
3. **退出码是接口**：0 成功、非 0 失败，且**失败码要有语义**。注意：某些运行时（如某些沙箱下的 Windows GUI 进程）退出码会被环境伪影污染，此时**以日志中的成功标记为准**，并把这条写进文书，否则下一个人还会误判。
4. **不许"口头通过"**：命令没跑、断言没绿，就不算完成。检查点失败 = 任务未完成。

## 5. 状态、副作用与可逆性

- **一切副作用都要能撤销**：加锁要释放、注入样式要能移除、监听要有 disposer、临时文件要清理。做不到可逆的操作用"必须经确认"来补偿。
- **不可逆操作单独隔离**：换目录、删树、覆盖用户数据这类操作，收敛到一个模块、写成全同步的纯逻辑，并且**每条失败分支都要有单测**。
- **状态读写收敛**：状态文件/锁文件的读写集中在少数几个函数（`readState/writeState/...`），不散落在业务代码里。散落 = 迟早出现"两处写法不一致"。
- **删除可能含链接（junction/symlink）的目录，必须走安全删除**：普通递归删除在某些命令下会**跟随链接删掉目标**，把别人的数据掏空（实测：目标文件全没、目录还在）。自己的删除器要显式跳过链接；判断年龄用 **birthtime 而非 mtime**（内容一变 mtime 就刷新）。
- **写别人的模板文件前，先看那个文件的"末行形态"**：往 `[]`/`{}` 这种空文档字面量后面追加内容会产生**第二个文档**（YAML/JSON 直接损坏）。"幂等写入"必须用**解析结果**判断，不能靠"名字出现过没有"。

## 6. 配置、凭据与机器相关值

1. **凭据永不入库**：密钥、token、证书、`.env`、带密码的导出文件。`.gitignore` 必须显式覆盖它们（连"曾经存在于工作区"都不要留——临时诊断目录里最容易漏出凭证明文）。
2. **提供 `*.example` 模板**：新克隆的人照着填，而不是猜。
3. **机器相关值不写死在代码里**：绝对路径、端口、用户名、盘符，一律走环境变量或配置，并有安全默认值（默认绑回环 `127.0.0.1`，不默认 `0.0.0.0`）。
4. **端口不假设固定**：被占用时自动回退，并把**实际端口**写到状态文件/日志里，让人能查到。
5. **改环境变量只对新进程生效**（`setx` 类工具如此）：脚本内部要显式带上当前值，别指望"我刚设过了"。

## 7. 日志与可观测性

- **关键路径必须留下可读的现场**：启动、就绪、降级、重试、失败、清理——每步一行，带时间与关键参数。
- **日志要留得下最后一句话**：进程崩溃时，"最后几行"往往就是唯一线索。子进程输出要**实时落盘 + 环形缓冲**（保留遗言），不要只在退出后收集。
- **日志按天轮转、保留 7 天**，避免无限增长；写入失败要降级到控制台而不是崩掉。
- **敏感信息脱敏**：路径中的用户名、token、cookie 不原样入日志；审计用途的日志只留必要预览（例如命令前 300 字）。
- **提供一键取证命令**：`--doctor` / `--diag` 之类，一条命令把所有现场打出来（版本、路径、关键环境变量、依赖完整性、日志尾部）。排障时间基本花在"收集信息"上，这一步自动化收益最大。

## 8. 依赖与构建

- **锁文件入库**（`package-lock.json` / `pnpm-lock.yaml` 等），依赖版本**精确锁定**，禁止 `latest`。
- **构建可离线、可复现**：镜像/缓存目录显式配置（例如 `npm_config_cache`、`ELECTRON_MIRROR`），不依赖"我这台机器恰好能连上"。
- **剪枝按文件数优先，不按字节数**：安装耗时与文件数强相关（解压 + 杀软逐文件扫描）。`.map`/`.d.ts`/`docs`/`test` 直接剪。
- **平台二进制要走"不打包进归档"通道**（`asarUnpack` / `extraResources` 类机制），放进归档里系统加载器读不到。
- **体积/文件数设基线**：把"应该有 N 个文件"写进门禁，防悄悄缺文件。

## 9. 安全底线

- 本地服务**只绑回环**；跨源请求走**白名单**，不用 `*`。
- 任何"把本地文件交给渲染层/浏览器"的场景，走**受控的本地 HTTP 供给**（带 MIME 白名单、`no-store`、时间戳破缓存），不要指望页面能直接读 `file://`——现代浏览器一律拒绝。
- 路径参数必须**校验存在性 + 扩展名白名单 + 规范化**后再使用。
- 不 `eval`、不拼接执行外部输入；子进程参数用**数组**传递，不要拼字符串（路径含空格必炸）。

## 10. 文档与注释的边界

- 代码里回答「怎么做的、为什么这么做」；文书回答「做什么、做到哪了、怎么验证」。
- **每个项目至少三份文档**：规范（本文体系）、进度事实源、变更日志。缺一个，交接就靠口口相传。
- 交付物要写清**怎么用、有什么已知限制**（例如"未签名，首次运行会有 SmartScreen 提示，属预期"）。
